# @browser-auth/core

Experimental TypeScript SDK and `browser-auth` CLI for human-supervised authentication in an existing Chromium browser. Requires Node 22.18+ or 24+.

The SDK exports `createAuth`, `InMemoryStore`, package-owned option/result types, and a credential-store contract. `@browser-auth/core/protocol` provides plain parser functions for UI transports; `@browser-auth/core/tracing` provides opt-in OTLP export behind package-owned tracing interfaces. Internal library types and agent contracts are not part of the public API.

Configure a plain `model: { provider, model, apiKey?, baseURL?, headers? }`; the SDK owns the agent loop. Supported providers are `openai`, `anthropic`, `openai-compatible` (requires `baseURL`), and `gateway`. OpenAI supports `api: "responses" | "chat"`; compatible endpoints support `name`, `queryParams`, and `supportsStructuredOutputs`. Gateway supports `providerOptions.gateway: { order?, only?, models? }` for provider routing and fallback models, following AI SDK field names without exporting its types. Each call to the single `login(options)` method starts one flow. Consume `updates()`, collect human responses, and pass them to `respond()`; `result` settles after completion. Never log responses or CDP endpoints. The CLI mirrors this as the sole `login` browser command, accepts operation data through private `--input` JSON files, and exposes `accounts list/remove`. Its `--json` mode emits snapshots and accepts responses or cancellation over JSON lines; it never silently finishes a session.

Only process-local plaintext storage is bundled. Custom stores implement `list/get/save/delete` and own encryption and access control. An existing session emits a `session` interaction with choices generated from observed native controls (`logout`, `switch`, `add`, or `accounts`) plus the controller-appended `finish`; respond with a normal choose response to continue the same flow. `accounts` opens a native menu for discovery and does not assume entries exist. Finish returns `already-signed-in`, logout returns `signed-out`, and credential login or completed account change returns `authenticated`, without outcome confirmation. These model-inferred outcomes are not identity attestation. Switching/adding never falls back to logout. `accountId` selects only a saved credential record if credentials are needed. `forgetCredentials: true` requires it and applies only if logout is selected. Passkeys, CAPTCHAs, and similar external challenges are completed in the original browser, not bypassed.

Read the root README, SECURITY.md, and AGENTS.md in the source repository for the full lifecycle, threat model, tests, and contribution instructions.
